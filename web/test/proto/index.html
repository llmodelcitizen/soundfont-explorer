M0b browser-side validation prototypes

Serve with python3 web/test/proto/serve.py from the repo root (Range-capable; python3 -m http.server is not). Each page shows its numbers, stores them in window.__results and sets the title to DONE when finished.

  1. decode-probe.html — M0b-2/5: native decodeAudioData vs WASM, worker pool throughput (N = 1, 2, 4).
  2. ab-switch.html — M0b-3: gapless two-variant schedule, A/B every 100 ms for 60 s with 10 ms ramps; drift, voices, click proxies. (10 s · hard-cut control · synthetic)
  3. pack-fetch.html — M0b-6: SFPK whole vs header + member Range, keydown → start() warm / cold.

On a phone / another machine

Open http://<workstation LAN IP>:8765/web/test/proto/, tap Start on each page (the click creates the AudioContext), wait for the title to read DONE, then copy the JSON block at the bottom (long-press / select all) and paste it into docs/validation.md. Safari needs the page to be reached over HTTP on the LAN (no HTTPS required for Web Audio).

Headless automation

cd web/test/proto && npm install && npx playwright install chromium
node run-probes.mjs                       # all three pages, JSON on stdout
node run-probes.mjs ab-switch --seconds=5 # quick
